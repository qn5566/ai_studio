# 第二階段練習：目標價與原文證據

本練習接續已跑通的 Gemini 結構化輸出。學習重點：**格式驗證通過，不代表內容符合原文。**

## 程式流程

1. `schemas.py` 定義 `target_price_evidence`，未提及目標價時與 `target_price` 一起回傳 `null`。
2. `test_gemini.py` 的 Prompt 要求只抽取原文明確提及的目標價，附上逐字引文。
3. `evidence.py` 檢查欄位配對、引文是否存在於標題或內文，以及明確目標價數字是否一致；失敗時拋出 `ValueError`，不默默接受結果。
4. `target_price_cases.json` 保留人工預期答案：有目標價為 `1400.0`，只有營收或目前股價為 `null`。

證據檢查只支援明確的中文「目標價」或英文 `target price` 與阿拉伯數字報價。它不能完整判斷否定句、公司歸屬、幣別、多個目標價或金額單位；這些需要擴充資料與人工核對。模型漏掉目標價而回傳兩個 `null`，也要靠人工標註案例才能發現。

## 本機測試，不呼叫模型

在 `fin-signal-service` 資料夾，使用已安裝專案及開發依賴的 Python：

```bash
python3 -m pytest tests -q
```

測試使用人工建立的模型回應，確認可接受正常資料、拒絕捏造引文、營收或股價冒充目標價，以及金額不一致。**這些測試通過並不表示 Gemini 已答對三筆新聞。**

## 真實模型評估

確認環境已安裝 `google-genai` 且已設定 `GEMINI_API_KEY` 後執行：

```bash
python3 test_gemini.py
```

這會呼叫 Gemini 三次，可能產生費用。程式逐筆顯示預期值、實際值與原文證據；任一案例失敗時以非零狀態結束。不要把金鑰寫入檔案或提交到 Git。

目前這是獨立的手動評估程式，尚未把 Gemini 接入 FastAPI。原有關鍵字服務也會回傳它抽取到的原文字串作為證據。

複習題：為何「營收 1400 億元」不能用來支持 `target_price=1400.0`？引文存在於新聞中，還有哪些情況可能判斷錯誤？
