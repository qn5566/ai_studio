QUESTION 03 · TDD 與 Pydantic 實戰隨堂考（最新）

敏捷 TDD 開發：要新增功能，第一步先改誰？

當我們要在 NewsAnalysisRequest 加上 source 欄位，並在 SignalAnalysisResponse 加上 target_price 目標價時，按照測試驅動開發（TDD）紅綠燈規範，第一步應該修改哪一個檔案？

查看你的答題歷程與實作解析

你的選擇

B. 先改 tests/test_signal.py（先寫期待的測試，形成紅燈）

完全正確！ 在金融量化工程中，先寫測試等於先確認業務規格與 API 契約，確保「紅燈（失敗）」能被精準捕捉。

課堂實戰三部曲（Red ➜ Green ➜ Refactor）

🔴 紅燈（Red）
在 tests/test_signal.py 加入 assert req.source == "Bloomberg" 與 assert result.target_price == 250.0。執行 pytest 精準噴出 AttributeError: 'NewsAnalysisRequest' object has no attribute 'source'。
🟢 綠燈（Green）
你親手在 schemas.py 定義 source: str = Field(default="UNKNOWN", ...) 與 target_price: float | None = Field(default=None, gt=0.0, ...)；接著在 service.py 補齊正規表達式抽取目標價，測試立即轉為通過！
🔵 重構（Refactor）
透過 ruff check . --fix 修復 PEP 8 長度與格式，最終以 pytest -v 達成 4 passed in 0.47s 全綠燈！
跨語言思維打通
Pydantic 的 BaseModel 與 Field(gt=0.0) 就等於 Flutter 的 freezed/json_serializable 加上資料約束，在接收請求時就自動阻絕髒資料。
QUESTION 01 · 依賴分類

部署時，還需要開發工具嗎？

如果把專案部署到伺服器，只提供 API，不在上面跑測試或檢查程式碼，pytest 和 Ruff 通常還需要安裝嗎？

查看你的回答與解說

你當時的回答

不用吧

答對了。只提供 API 時，通常不用安裝這兩個開發工具。

完整參考答案

依目前專案，FastAPI、Uvicorn、Pydantic 是服務運作需要的依賴。pytest 和 Ruff 可留在開發環境或 CI 裡使用。

目前 HTTPX 也放在 dev 群組，供測試使用；但在其他專案裡，它也可能是正式服務需要的工具，應依實際用途分類。

容易混淆
dev 是你定義的額外依賴群組，不代表這些套件禁止在正式環境使用。不選 dev，也不會自動移除已安裝的工具。
QUESTION 02 · 安裝指令

這行指令，實際安裝了什麼？

python3 -m pip install -e ".[dev]"

請用自己的話說明：安裝哪個專案、dev 是什麼、-e 有什麼用途？

查看你的回答與解說

你當時的回答

主要是使用 pip 的工具去安裝 [dev] 裡面的依賴

你說中了 dev 的用途。再補上「目前專案」與「可編輯模式」，答案就完整了；補充後你表示已了解。

逐段拆解

python3 -m pip
使用這個 Python 環境裡的 pip。
install
執行安裝。
.
安裝目前資料夾的專案，以及基本 dependencies。
[dev]
額外安裝專案定義的 dev 群組依賴。
-e
可編輯模式；修改一般 Python 原始碼後，通常不必重新安裝。

完整參考答案

使用這個 Python 的 pip，以可編輯模式安裝目前專案，並一起安裝基本依賴和 dev 群組的開發工具。

容易混淆
不只是安裝 dev。修改依賴或部分套件設定後，仍可能要重新安裝。引號則避免 shell 把方括號當成檔名比對符號。
